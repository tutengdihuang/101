# 容器技术概览 - 揭开容器的神秘面纱

> 容器不是虚拟机，它只是一个被"关在笼子里"的进程

## 一个问题引发的思考

假设你是一个房东，有一栋大房子要出租。你有两种选择：

**方案一：盖隔断间**
- 用轻质墙把大房子隔成小房间
- 每个房间共用水电煤气管道
- 租客只能看到自己的房间
- 成本低、速度快

**方案二：盖独立小楼**
- 每个租客一栋独立小楼
- 每栋楼有独立的水电煤气
- 完全隔离，互不影响
- 成本高、建设慢

这两种方案，就对应了**容器**和**虚拟机**的区别！

## 容器 vs 虚拟机

### 虚拟机：每人一栋独立小楼

```
┌─────────────────────────────────────────────────────┐
│                    宿主机硬件                        │
├─────────────────────────────────────────────────────┤
│                   宿主机操作系统                      │
├─────────────────────────────────────────────────────┤
│                  Hypervisor (VMware/KVM)            │
├────────────────┬────────────────┬───────────────────┤
│     虚拟机 1    │     虚拟机 2    │     虚拟机 3      │
│  ┌──────────┐  │  ┌──────────┐  │  ┌──────────┐    │
│  │ Guest OS │  │  │ Guest OS │  │  │ Guest OS │    │
│  ├──────────┤  │  ├──────────┤  │  ├──────────┤    │
│  │   App    │  │  │   App    │  │  │   App    │    │
│  └──────────┘  │  └──────────┘  │  └──────────┘    │
└────────────────┴────────────────┴───────────────────┘
```

每个虚拟机都有完整的操作系统，就像每栋小楼都有独立的水电煤气系统。

### 容器：共享基础设施的隔断间

```
┌─────────────────────────────────────────────────────┐
│                    宿主机硬件                        │
├─────────────────────────────────────────────────────┤
│                   宿主机操作系统                      │
├─────────────────────────────────────────────────────┤
│                   Docker Engine                     │
├────────────────┬────────────────┬───────────────────┤
│    容器 1      │    容器 2       │    容器 3         │
│  ┌──────────┐  │  ┌──────────┐  │  ┌──────────┐    │
│  │   App    │  │  │   App    │  │  │   App    │    │
│  └──────────┘  │  └──────────┘  │  └──────────┘    │
└────────────────┴────────────────┴───────────────────┘
        ↑                ↑                ↑
        └────────────────┴────────────────┘
                  共享宿主机内核
```

所有容器共享宿主机的操作系统内核，就像所有隔断间共享同一套水电煤气管道。

### 对比总结

| 特性 | 虚拟机 | 容器 |
|------|--------|------|
| 隔离级别 | 硬件级别 | 进程级别 |
| 启动时间 | 分钟级 | 秒级 |
| 资源占用 | GB 级 | MB 级 |
| 性能损耗 | 5-15% | 接近原生 |
| 安全性 | 高 | 中 |
| 生活比喻 | 独立小楼 | 隔断间 |

## 容器的本质：被"关在笼子里"的进程

容器本质上就是一个进程，只不过这个进程被 Linux 内核的几个特性"关在笼子里"：

1. **Namespace**：让进程"看不见"其他进程（视觉隔离）
2. **Cgroups**：限制进程能用多少 CPU、内存（资源配额）
3. **OverlayFS**：给进程一个独立的文件系统（独立空间）

就像把一个人关在一个房间里：
- **Namespace** = 房间的墙壁（看不到外面）
- **Cgroups** = 水电配额（限制资源使用）
- **OverlayFS** = 房间里的家具（独立的生活空间）

```
┌─────────────────────────────────────────────────────┐
│                     容器 = 笼子                      │
│  ┌─────────────────────────────────────────────┐   │
│  │              Namespace (墙壁)                │   │
│  │  ┌───────────────────────────────────────┐  │   │
│  │  │           Cgroups (配额)              │  │   │
│  │  │  ┌─────────────────────────────────┐  │  │   │
│  │  │  │      OverlayFS (家具)           │  │  │   │
│  │  │  │  ┌───────────────────────────┐  │  │  │   │
│  │  │  │  │        进程 (人)          │  │  │  │   │
│  │  │  │  └───────────────────────────┘  │  │  │   │
│  │  │  └─────────────────────────────────┘  │  │   │
│  │  └───────────────────────────────────────┘  │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

## 动手验证：容器就是进程

让我们用实验来验证"容器就是进程"这个说法。

### 实验 1：启动一个容器

```bash
# 启动一个 nginx 容器
docker run -d --name mynginx nginx

# 查看容器
docker ps
```

**实验输出**：
```
CONTAINER ID   IMAGE   COMMAND                  STATUS         NAMES
a1b2c3d4e5f6   nginx   "/docker-entrypoint.…"   Up 10 seconds  mynginx
```

### 实验 2：找到容器对应的进程

```bash
# 查看容器的 PID
docker inspect mynginx | grep -i pid
```

**实验输出**：
```json
"Pid": 12345,
"PidMode": "",
"PidsLimit": null,
```

### 实验 3：在宿主机上查看这个进程

```bash
# 在宿主机上查看进程
ps aux | grep 12345
```

**实验输出**：
```
root     12345  0.0  0.1  nginx: master process nginx -g daemon off;
```

看到了吗？容器里的 nginx，在宿主机上就是一个普通的进程！

### 实验 4：杀掉进程 = 停止容器

```bash
# 杀掉进程
kill 12345

# 查看容器状态
docker ps -a | grep mynginx
```

**实验输出**：
```
a1b2c3d4e5f6   nginx   "/docker-entrypoint.…"   Exited (0)   mynginx
```

进程被杀，容器就停止了。这再次证明：**容器就是进程**！

## Docker 的三大核心技术

理解了容器的本质，接下来我们深入学习 Docker 的三大核心技术：

### 1. Namespace - 隔离的魔法

Namespace 让进程拥有独立的"视野"，看不到其他进程。

Linux 提供了 8 种 Namespace：

| Namespace | 隔离内容 | 生活比喻 |
|-----------|---------|---------|
| PID | 进程 ID | 每个房间有独立的门牌号 |
| NET | 网络 | 每个房间有独立的网线 |
| MNT | 文件系统挂载点 | 每个房间有独立的储物柜 |
| UTS | 主机名 | 每个房间有独立的名字 |
| IPC | 进程间通信 | 每个房间有独立的对讲机 |
| USER | 用户 | 每个房间有独立的住户名单 |
| CGROUP | Cgroup 根目录 | 每个房间有独立的配额表 |
| TIME | 系统时间 | 每个房间有独立的时钟 |

### 2. Cgroups - 资源的管家

Cgroups（Control Groups）限制进程能使用多少资源。

| 子系统 | 控制内容 | 生活比喻 |
|--------|---------|---------|
| cpu | CPU 使用率 | 每天能用几度电 |
| memory | 内存使用量 | 房间能放多少家具 |
| blkio | 磁盘 IO | 每天能用多少水 |
| cpuset | CPU 核心绑定 | 只能用哪几个插座 |
| pids | 进程数量 | 房间能住几个人 |

### 3. OverlayFS - 分层的文件系统

OverlayFS 让多个目录"叠加"成一个目录，实现镜像的分层存储。

```
┌─────────────────────────────────────┐
│           merged (合并层)            │  ← 容器看到的文件系统
├─────────────────────────────────────┤
│           upper (可写层)             │  ← 容器的修改写在这里
├─────────────────────────────────────┤
│           lower (只读层)             │  ← 镜像的内容
└─────────────────────────────────────┘
```

就像透明胶片叠加：
- 底层胶片是镜像（只读）
- 上层胶片是容器的修改（可写）
- 从上往下看，就是容器看到的文件系统

---

## 核心要点总结

1. **容器不是虚拟机**：容器是进程级隔离，虚拟机是硬件级隔离
2. **容器就是进程**：容器本质上是一个被 Linux 内核特性"关在笼子里"的进程
3. **三大核心技术**：
   - Namespace：隔离（让进程看不到其他进程）
   - Cgroups：限制（限制进程能用多少资源）
   - OverlayFS：分层（实现镜像的分层存储）

记住这个公式：**容器 = Namespace + Cgroups + OverlayFS**
