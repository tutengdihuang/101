# 监控体系概述

> 一句话概括：监控系统就像汽车的仪表盘，让你随时掌握系统的"健康状况"。

## 核心概念

| 概念 | 大白话解释 | 生活比喻 |
|------|-----------|---------|
| **监控** | 持续观察系统状态 | 医生定期体检 |
| **指标** | 可量化的数据点 | 体温、血压、心率 |
| **告警** | 异常时主动通知 | 心电监护仪报警 |
| **可视化** | 用图表展示数据 | 体检报告的图表 |

## 核心组件介绍

### 1. Prometheus - 监控核心

**角色**：数据采集、存储、查询的核心引擎

**主要功能**：
- 定期抓取 Exporter 暴露的指标
- 存储时序数据（默认保留 7 天）
- 提供 PromQL 查询语言
- 评估告警规则

**生活比喻**：
```
Prometheus 就像医院的检验科：
- 定期采集样本（抓取指标）
- 保存检验结果（存储数据）
- 提供查询服务（PromQL）
- 发现异常指标（告警规则）
```

### 2. Grafana - 可视化平台

**角色**：数据可视化和 Dashboard 管理

**主要功能**：
- 连接多种数据源（Prometheus、MySQL 等）
- 创建丰富的图表和 Dashboard
- 支持变量和模板
- 配置告警通知

**生活比喻**：
```
Grafana 就像体检报告的图表：
- 把枯燥的数字变成直观的图表
- 一眼就能看出健康状况
- 可以对比历史数据
```

### 3. AlertManager - 告警管理

**角色**：告警通知的管理和分发

**主要功能**：
- 接收 Prometheus 发送的告警
- 告警分组、去重、静默
- 路由到不同的接收器
- 发送通知（邮件、Webhook、钉钉等）

**生活比喻**：
```
AlertManager 就像医院的急诊分诊台：
- 接收各种报警信息
- 判断紧急程度（分组）
- 避免重复通知（去重）
- 通知对应的医生（路由）
```

### 4. Exporter - 数据采集器

**角色**：采集特定系统的指标

**常见 Exporter**：
| Exporter | 采集对象 | 主要指标 |
|----------|---------|---------|
| Node Exporter | 节点 | CPU、内存、磁盘、网络 |
| Kube-State-Metrics | K8s 资源 | Pod、Deployment、Service 状态 |
| cAdvisor | 容器 | 容器资源使用 |
| Tekton Metrics | Tekton | Pipeline 执行情况 |
| ArgoCD Metrics | ArgoCD | 应用同步状态 |

**生活比喻**：
```
Exporter 就像各种体检设备：
- 血压计测量血压（Node Exporter 测量节点）
- 心电图测量心脏（cAdvisor 测量容器）
- 血液检测仪分析血液（KSM 分析 K8s 资源）
```

## 数据流详解

### 完整数据流

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              数据流详解                                      │
│                                                                             │
│  1. 指标暴露                                                                │
│     ┌──────────┐                                                           │
│     │ Exporter │ ──▶ /metrics (HTTP 端点)                                  │
│     └──────────┘                                                           │
│           │                                                                 │
│           │ 每 30 秒                                                        │
│           ▼                                                                 │
│  2. 指标抓取                                                                │
│     ┌──────────┐                                                           │
│     │Prometheus│ ◀── ServiceMonitor (定义抓取规则)                         │
│     └──────────┘                                                           │
│           │                                                                 │
│           │ 存储到 TSDB                                                     │
│           ▼                                                                 │
│  3. 数据存储                                                                │
│     ┌──────────┐                                                           │
│     │  TSDB    │ ──▶ 时序数据库（保留 7 天）                                │
│     └──────────┘                                                           │
│           │                                                                 │
│           ├─────────────────────────────────────┐                          │
│           │                                     │                          │
│           │ 每 30 秒评估                        │ PromQL 查询               │
│           ▼                                     ▼                          │
│  4. 规则评估                              5. 数据可视化                     │
│     ┌──────────┐                           ┌──────────┐                    │
│     │  Rules   │                           │ Grafana  │                    │
│     └──────────┘                           └──────────┘                    │
│           │                                     │                          │
│           │ 触发告警                            │ Dashboard                 │
│           ▼                                     ▼                          │
│  6. 告警处理                              ┌──────────┐                      │
│     ┌──────────┐                          │  用户    │                      │
│     │AlertMgr  │                          │ 查看图表 │                      │
│     └──────────┘                          └──────────┘                      │
│           │                                                                 │
│           │ 分组 → 去重 → 路由                                              │
│           ▼                                                                 │
│  7. 通知接收                                                                │
│     ┌──────────┐                                                           │
│     │ Webhook  │ ──▶ 钉钉/企业微信/邮件                                    │
│     └──────────┘                                                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**两条数据流路径**：

1. **告警路径**：Prometheus → 规则评估 → AlertManager → 通知
2. **可视化路径**：Prometheus → Grafana → 用户查看 Dashboard

### 关键时间点

| 阶段 | 默认间隔 | 说明 |
|------|---------|------|
| 指标抓取 | 30s | Prometheus 抓取 Exporter |
| 规则评估 | 30s | 评估告警规则 |
| 告警触发 | for 时间 | 持续满足条件才触发 |
| 告警分组 | 30s | 等待收集同组告警 |
| 重复通知 | 4h | 同一告警重复发送间隔 |

## 监控范围

### 基础设施监控

| 监控对象 | 主要指标 | 数据来源 |
|---------|---------|---------|
| 节点 | CPU、内存、磁盘、网络 | Node Exporter |
| Pod | 资源使用、状态、重启 | cAdvisor + KSM |
| 容器 | CPU、内存、文件系统 | cAdvisor |

### DevOps 组件监控

| 监控对象 | 主要指标 | 数据来源 |
|---------|---------|---------|
| Tekton | Pipeline 执行情况 | Tekton Metrics |
| ArgoCD | 应用同步状态 | ArgoCD Metrics |

### 告警规则

| 类别 | 告警规则 | 严重级别 |
|------|---------|---------|
| CI/CD | Pipeline 失败、执行超时 | critical/warning |
| 基础设施 | CPU/内存/磁盘过高 | critical/warning |
| Pod | CrashLoopBackOff、OOM | critical |
